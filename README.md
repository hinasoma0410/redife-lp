# デジタル御用聞き リダイフ 公式サイト

中小企業・個人事業主向けの「デジタル御用聞き リダイフ」公式サイト用リポジトリです。

## 方針
- 商品名ではなく、日々の業務の困りごとを入口にする
- AI・業務ツール・Web制作を目的に応じて使い分ける
- 未確認の実績・成果・料金条件は掲載しない
- 依存ライブラリを最小化し、静的サイトとして安全性・速度・保守性を優先する

## セキュリティ
- 外部JavaScriptライブラリなし
- APIキーや顧客情報をフロントエンドへ保存しない
- CodeQLによるJavaScript静的解析を実施
- GitHub ActionsはDependabotで更新を監視する

## 記事の掲載・更新

- トップページの `#guides` は、公開済みの新着記事を最大2件だけ掲載する。
- 記事は公開日が新しい順。同日公開は現在の掲載順を維持し、新たに公開した記事を先頭に追加する。更新日の変更だけで新着記事に戻さない。
- 新記事の公開時は `/guides/` の該当カテゴリへ追加し、トップページは上位2件に入れ替える。トップから外した記事とそのURLは削除しない。
- 記事一覧のカテゴリは、公開済みの記事があるものだけ表示する。未公開・確認中の記事は掲載しない。
- 各記事の末尾に「次に読む記事」を最大2件と関連サービスへのリンク、`/guides/` へ戻るリンクを置く。記事数が少ない間は関連する1件だけでよく、自己リンクや同じ記事への重複リンクで件数を埋めない。該当サービスページからも記事へ案内する。
- 新記事と一覧の表示・構造化データ・サイトマップを同時に更新する。公開日と更新日は実際の日付を使用する。
- 一覧が増えたら、1ページ10件を目安にカテゴリ別ページやページ送りを用意する。これは今後の更新方針で、現在は2記事の静的一覧。

### 記事の探し方

- トップの見出しは「お役立ち記事一覧」とし、掲載する記事は引き続き新しい2件まで。
- 一覧は「Googleマップ・お店の情報」「LP・ホームページ」「日々の仕事・AI活用」を基本の分類とする。関連する記事の初回公開時にカテゴリを追加し、空のカテゴリは表示しない。
- 分類の紹介文には「営業時間を変えたい」「何を作るか決めたい」「手作業を減らしたい」など、記事で解決できる困りごとを書く。


## サイトマップの更新日

- `lastmod` はページ単位で、本文・図解・重要なリンク・構造化データなどを実質的に変更した公開日を記録する。全URLへ一律に当日を入れない。
- 共通メニューや著作権表記だけの軽微な更新で、記事の公開日・更新日を進めない。共通リンクの大幅な再編は、影響を確認して個別に判断する。
- 記事の図解や本文を変更したときは、表示上の更新日、Article.dateModified、該当URLのlastmodを揃える。datePublishedは維持する。
- 新規ページは公開日にサイトマップへ追加する。未公開・転送専用・noindexのURLは含めない。
- FAQPageは表示中の質問・回答と一致させる。GoogleのFAQリッチリザルトは終了しているため、特別表示や順位向上を約束しない。

### 記事のアイキャッチとタイトル

- 中小企業の経営者へ、落ち着きと親しみやすさが伝わるデザインに統一する。生成りの紙、深緑の明朝見出し、控えめなセージ色の鉛筆・水彩風イラスト、右下の「リダイフ」の文字を基本にする。
- アイキャッチは1200×630のJPEG。内容に合う短い見出しとモチーフを使い、架空の人物・実績・画面を加えない。画像は記事本文・og:image・twitter:image・Article.imageで統一する。説明用の図解は本文に残す。
- タイトルは単語や意味のまとまりを途中で分けない。画像生成時は各行の文言を指定し、助詞だけ・語尾だけの行を作らない。長い場合は文字量・文字サイズ・配置を調整する。
- 記事H1はarticle-titleとphraseで意味のまとまりを指定する。長いまとまりを無理に一行へ固定せず、320px幅でも収まる位置で分割する。H1とArticle.headlineは同じ文言にする。
- 公開前に320px・390px・768px・デスクトップで、実際の日本語フォント読込後の改行・横はみ出し・画像の文字切れを確認する。記事一覧・関連記事でも語尾だけの行が目立たないか確認する。

### 本文の図解

- アイキャッチとは別に、読者が文章だけより理解・判断しやすくなる箇所へ図解を入れる。比較、手順、判断の分岐、全体と部分の関係を優先する。
- 1図につき伝えることを1つに絞り、必要な段落の近くへ配置する。枚数を埋めるための装飾画像や、同じ文を並べただけのカードは増やさない。
- 選択肢には矢印と行き先、工程には順序、比較には共通の評価軸を示す。判断に影響する条件や例外は省略せず、図の近くで読めるようにする。
- 単純な分岐や比較は、スマホで文字を読めるHTML/CSSを優先し、該当する手順へのリンクも付ける。イラストが理解を助ける場合はImagegenを使い、承認済みの色・雰囲気に揃える。
- 図だけに重要な情報を閉じ込めず、本文にも説明を残す。画像の場合は代替テキストを付け、架空の管理画面を実際の操作画面として使わない。
- 公開前に320px・390px・PCで読みやすさ、自然な改行、矢印の対応、リンク先、本文・一次情報との整合を確認する。
