# デジタル御用聞き リダイフ 公式サイト

中小企業・個人事業主向けの「デジタル御用聞き リダイフ」公式サイト用リポジトリです。

## 方針
- 商品名ではなく、日々の業務の困りごとを入口にする
- AI・業務ツール・Web制作を目的に応じて使い分ける
- 未確認の実績・成果・料金条件は掲載しない
- 依存ライブラリを最小化し、静的サイトとして安全性・速度・保守性を優先する

## セキュリティ
- 外部JavaScriptライブラリなし
- APIキーや顧客情報をフロントエンドへ保存しない
- CodeQLによるJavaScript静的解析を実施
- GitHub ActionsはDependabotで更新を監視する

## 記事の掲載・更新

- トップページの `#guides` は、公開済みの新着記事を最大2件だけ掲載する。
- 記事は公開日が新しい順。同日公開は現在の掲載順を維持し、新たに公開した記事を先頭に追加する。更新日の変更だけで新着記事に戻さない。
- 新記事の公開時は `/guides/` の該当カテゴリへ追加し、トップページは上位2件に入れ替える。トップから外した記事とそのURLは削除しない。
- 記事一覧のカテゴリは、公開済みの記事があるものだけ表示する。未公開・確認中の記事は掲載しない。
- 各記事の末尾に「次に読む記事」を最大2件と関連サービスへのリンク、`/guides/` へ戻るリンクを置く。記事数が少ない間は関連する1件だけでよく、自己リンクや同じ記事への重複リンクで件数を埋めない。該当サービスページからも記事へ案内する。
- 新記事と一覧の表示・構造化データ・サイトマップを同時に更新する。公開日と更新日は実際の日付を使用する。
- 一覧が増えたら、1ページ10件を目安にカテゴリ別ページやページ送りを用意する。これは今後の更新方針で、現在は2記事の静的一覧。

### 記事の探し方

- トップの見出しは「お店の集客・仕事に役立つヒント」とし、掲載する記事は引き続き新しい2件まで。
- 一覧は「Googleマップ・お店の情報」「LP・ホームページ」「日々の仕事・AI活用」を基本の分類とする。関連する記事の初回公開時にカテゴリを追加し、空のカテゴリは表示しない。
- 分類の紹介文には「営業時間を変えたい」「何を作るか決めたい」「手作業を減らしたい」など、記事で解決できる困りごとを書く。
