ホームページから問い合わせが来ないときの確認順

公開日：2026年9月28日執筆：山本 健太

問い合わせが来ないときは、まずフォームから送った内容を受信できるか確認します。受信に問題がなければ、訪問の少なさ、ページの説明、相談までの道筋を順に点検し、直す場所を一つに絞りましょう。

今の状態から読む送信・受信できるか未確認サイトへの訪問が少ない訪問はあるが相談されない

最初に「来ていない」のか「届いていない」のかを分ける

問い合わせがないと、記事を増やすか、ホームページを作り直すかで迷うかもしれません。その前に、フォームから送った内容を担当者が受け取れるかを確かめましょう。受信の問題なら、集客を増やしても解決しません。

この図は原因を断定する診断ではなく、確認する順番です。アクセス解析を入れていない場合も、まず送受信とページの点検から進められます。

1．テストを1件送り、受信まで確かめる

受信する担当者にテストだと伝えてから、「動作確認・返信不要」と分かる内容を1件送ります。本物の顧客情報は使わず、テストした時刻を控えてください。

  1. 普段お客様が使うフォームを開き、必須項目を入力して送ります。まずスマートフォンで試すと、入力やボタンの問題も確認できます。
  2. 成功表示が出たか、エラーで止まらないかを確認します。
  3. 担当者の受信箱・迷惑メールフォルダで、同じ内容が届いたか確認します。フォームに受付一覧がある場合は、そこにも記録があるか照合します。
  4. 計測を設定している場合は、相談完了イベントも確認します。テスト分は実際の相談件数と分けて記録します。

成功表示だけで、メールが受信箱まで届いたとは判断できません。届かない場合は、再送を繰り返す前に、通知先アドレス、フォームサービスの受付記録、迷惑メールへの振り分けを確認します。設定が分からなければ、テスト日時・対象URL・表示された結果を制作会社や管理担当者に伝えます。

自動返信がないフォームもあります。送信者に返信が来ないことと、事業者側に通知が届かないことは分けてください。LINE・電話など別の窓口があるなら、そちらでの相談も合わせて確認します。

2．訪問が少ないなら、検索語と入口のページを見る

受信できると確認できたら、「そもそも見られているか」を調べます。アクセス数の合計だけでなく、依頼を検討している人がサービスの説明にたどり着いているかを見ましょう。

Search Consoleで、検索からの入口を確認する

  1. Search Consoleで自社サイトを選び、「検索パフォーマンス」の検索結果を開きます。
  2. まず直近28日間など、まとまった期間を選びます。比較するなら、その前の同じ長さの期間に揃えます。
  3. 「ページ」で問い合わせにつなげたいページを選び、「クエリ」でどんな検索語に表示されたかを見ます。
  4. 表示回数とクリック数を確認します。表示が少ない場合は、先にURL検査で検索登録の状態も確認します。

たとえば制作サービスのページなのに、採用情報を探す検索語ばかりで見られているなら、想定する訪問者とずれている可能性があります。逆に、表示回数がごく少ないうちは、クリック率の上下だけでタイトルの良し悪しを決められません。

各指標の定義はGoogle公式：検索パフォーマンスの見方で確認できます。Search Consoleに表示される検索語が、すべての検索語ではない点にも注意してください。

GA4で、どのページから来ているかを確認する

GA4の「ランディング ページ」レポートでは、訪問の入口になったページを確認できます。「トラフィック獲得」では、検索・紹介などの流入経路を分けて見られます。レポートの配置は設定により異なるため、見つからなければGA4内の検索でレポート名を探してください。

ランディング ページの表で対象のページを探し、必要なら「セッションの参照元 / メディア」を追加すると、どこから来た訪問かを分けて見られます。操作はGoogle公式：ランディング ページ レポートで確認できます。

記事への訪問はあっても、依頼内容を説明するページへ進んでいなければ、記事の中で次に知りたくなる情報へのリンクを点検します。無関係な記事から、一律に相談へ誘導する必要はありません。

数字がゼロでも、訪問ゼロとは限りません

計測が未設定、別のプロパティを見ている、処理待ちなどの可能性があります。同意が必要なサイトでは、許可しなかった訪問が計測されないこともあります。まず設定を確認し、計測できた範囲で判断してください。

3．訪問があるなら、依頼前の疑問と相談への道筋を点検する

社長自身では分かっていることも、初めてページを読む人には伝わっていない場合があります。サービスページを開き、次の4つに答えが見つかるか確認してください。

  • 自分も対象か：どんな会社・お店の、どの困りごとを扱うか。
  • 何を頼めるか：具体的な作業、できる範囲と対象外。
  • 依頼の条件は何か：料金または見積もり方法、必要な準備、対応地域。
  • 相談後はどうなるか：連絡手段、相談の流れ、分かっている返信の目安。

「高品質」「柔軟に対応」だけでは、依頼内容を判断しにくくなります。実際に提供できる仕事や確認事項を具体的に書き、未確認の料金や納期は約束しないようにしましょう。

スマートフォンで、相談ボタンから先まで進む

相談ボタンを見つけられるか、押すと説明どおりの窓口が開くか、必須項目が多すぎないかを確認します。「問い合わせ」より「制作について相談する」など、行き先が分かる表現が合う場合もあります。契約や購入と誤解されるボタンになっていないかも見直しましょう。

GA4でボタンのクリックを計測している場合、クリックと送信成功は別々に見ます。generate_leadは問い合わせ送信に使える推奨イベントですが、実装が必要です。GA4を入れただけで、すべてのフォームの成功が自動で正しく記録されるとは限りません。Google公式：推奨イベント

直す場所を一つ決め、同じ条件で確かめる

確認結果から、次の作業を選ぶ
確認できたこと次にすること確認する結果
通知が届かないフォーム・通知先を直すテスト内容を受信できたか
必要なページが未登録URL検査の理由を確認する検索登録の状態
記事からサービスへ進めない内容に合う関連リンクを置くサービスページへの移動
相談前の条件が分からない提供範囲・見積もり方法を補う相談の内容と件数

表が見切れる場合は横にスクロールできます。

変更日と内容をメモし、前後で対象期間・ページ・流入経路を揃えて確認します。訪問や相談が少ないときは観察期間を延ばしてください。数字が増えても、季節や広告など他の変化があれば、今回の修正だけの効果とは言い切れません。

既存ページの説明を直すか、別のページを作るかで迷ったら、ホームページとLPの選び方も参考にしてください。ページ数を増やす前に、そのページで何を判断してもらうかを決めましょう。

どこで止まっているか分からないときは

今のホームページのURLと、確認できたことをお知らせください。受信・集客・説明のどこから手をつけるか、一緒に整理します。
